# OA UI/UX Reference

Load this for new UI design or visual direction work. Routine fixes, minor CSS changes, and non-UI tasks do not need it.

Reference priority: user-provided design, then the existing project design system, then beui.dev, then React Bits, then custom implementation.

- Inspect the project's components, design system, styling, layout, and architecture first. Preserve existing conventions unless a redesign is requested.
- Prefer screenshots, HTML, mockups, or reference URLs supplied by the user before any external source.
- Use https://beui.dev/ for component and layout inspiration when new design is needed. Study typography, spacing, hierarchy, responsiveness, and interaction.
- Fall back to https://reactbits.dev/ only when beui.dev gives nothing suitable. Keep effects compatible with the project's stack and avoid unnecessary animation.
- When neither source fits, follow established UI/UX principles and project conventions. Create an appropriate component without forcing an unrelated reference.
- Adapt references rather than copying them. Respect licenses and attribution. Reuse existing dependencies and components.
- Verify desktop and mobile layouts, interactions, and accessibility before reporting done.
- Report which reference was used, or state that no external reference was necessary. Never claim a reference that was not checked.
