# Installation, Update, and Uninstall

OA ships as source. Every runtime artifact is generated by one exporter, which is
idempotent, conflict-aware, and reversible.

## Requirements

- Node.js 20+ (developed on v24).
- One supported runtime: OpenCode v2, Claude Code, OpenAI Codex, Gemini CLI, GitHub
  Copilot, or any chat model (prompt pack).
- Optional: Overgeared Skills installed, for the Overgeared Skills skills OA reuses by name.

## Commands

```bash
# OpenCode, into this repository's .opencode/ (the verified setup)
node integrations/export.mjs --runtime opencode --to project

# OpenCode, global (~/.config/opencode) — explicit opt-in only
node integrations/export.mjs --runtime opencode --to global

# Other runtimes: default output is integrations/dist/<runtime>
node integrations/export.mjs --runtime claude
node integrations/export.mjs --runtime codex
node integrations/export.mjs --runtime gemini
node integrations/export.mjs --runtime copilot
node integrations/export.mjs --runtime chatgpt

# All file-based runtimes at once
node integrations/export.mjs --runtime all --to project

# Into a specific project directory
node integrations/export.mjs --runtime claude --to C:/path/to/project
```

Flags:

- `--check` — render and report without writing.
- `--list` — print the planned artifact paths and exit.
- `--force` — back up files that OA does not own (or that changed after export) and
  reclaim them.
- `--uninstall` — remove OA-owned files recorded in the manifest.

## How installation stays safe

- **Preflight.** Every artifact is rendered and every conflict detected *before* the
  first write, so a failed run cannot leave a half-written install.
- **Idempotent.** Re-running with unchanged content writes nothing new and reports no
  conflicts.
- **Conflict-aware.** OA never silently overwrites a file it does not own, or one the
  user edited after OA wrote it. Without `--force` it reports the conflict and stops;
  with `--force` it backs the file up under `<root>/oa-backups/<timestamp>/` first.
- **Reversible.** Each write is recorded in `<root>/oa-manifest.json` with a content
  hash. `--uninstall` removes only files whose hash still matches, and never deletes
  user edits or whole directories.

## Update

Re-run the same export command. Changed artifacts are rewritten; unchanged ones are left
alone. If you edited a generated file yourself, OA treats it as a conflict rather than
clobbering it (use `--force` to back up and reclaim).

## Uninstall

```bash
node integrations/export.mjs --runtime opencode --to project --uninstall
```

Files that changed after export are preserved and reported, so uninstall never destroys
your edits.

## Where artifacts land

| Runtime | Root | Layout |
| --- | --- | --- |
| OpenCode | `<dest>/.opencode` | `agents/oa-*.md`, `skills/<n>/SKILL.md`, `oa-delegation.md` |
| Claude Code | `<dest>/.claude` | `agents/oa-*.md`, `skills/<n>/SKILL.md`, `oa-permissions.json` |
| Codex | `<dest>/.codex` + `<dest>/.agents` | `agents/oa-*.toml`; `skills/<n>/SKILL.md` |
| Gemini CLI | `<dest>/.gemini` | `agents/oa-*.md`, `skills/<n>/SKILL.md` |
| GitHub Copilot | `<dest>/.github` | `agents/oa-*.agent.md`, `skills/<n>/SKILL.md` |
| ChatGPT / generic | `<dest>/prompt-pack` | `agents/oa-*.md`, `oa-system-pack.md`, `oa-skills.md` |

Each root carries its own `oa-manifest.json`.

## Activating delegation

The OpenCode export also writes `oa-delegation.md` at the config root: `.opencode/oa-delegation.md` for a project install, `~/.config/opencode/oa-delegation.md` for a global install. The file is inert until OpenCode is told to load it.

Add it to the `instructions` array in the config that governs the install. This is a one-time entry.

Global install, `~/.config/opencode/opencode.jsonc`:

```json
"instructions": ["~/.config/opencode/oa-delegation.md"]
```

Project install, the project's OpenCode config:

```json
"instructions": [".opencode/oa-delegation.md"]
```

Without the entry OpenCode installs the file but does not load it, and the orchestrator relies on the body in its agent file plus the `oa-orchestration` skill. On OpenCode the tool-level boundary is enforced by the orchestrator's permission rules and guardrail; the delegation instruction remains a behavioral rule.

## Choosing an entry point

The export installs the `oa-orchestrator` primary agent, nine specialist subagents, and the
shared `oa-orchestration` skill. It does not set `default_agent`; set it in the project or
global config if you want the orchestrator selected automatically.

```json
{ "default_agent": "oa-orchestrator" }
```

For the gated flow, select the orchestrator and load the shared skill:

```bash
opencode run --agent oa-orchestrator --auto "Load oa-orchestration, then <your request>"
```

The orchestrator retrieves first, chooses the specialists that apply, and runs the
independent passes concurrently. It cannot edit, shell, or use Code Mode `execute`, and it
can delegate only to the nine specialists. `docs/permissions.md` covers the exact rules and
what remains instruction-level.

## Legacy entry point

`integrations/opencode/export.mjs` still works and forwards to the unified exporter:

```bash
node integrations/opencode/export.mjs --target project|global|<dir>
```
